Project Background & Positioning
🚨 传统政务咨询核心痛点
传统政务问答长期受困于三座大山：一是长尾非结构化政策法规（4.4GB数据）检索召回率低，常规分词常发生关键词断裂；二是通用大模型幻觉频发，对法律法规与窗口材料严肃性缺乏精准溯源；三是政务系统跨域隔离严重，前端交互与底层接口难以低侵入集成。
💡 本系统核心破局方案
本项目构建基于 Spring AI 1.0 现代化反应式框架的 Dual-Agent 架构。自研“SQLite FTS5 短词精召 + 纯 CPU ONNX 语义精排”的高性能轻量 RAG 管道，结合轻量 Shadow DOM 悬浮智能体，实现 0 显卡成本、首字延迟 < 1.2s、权威可溯源的政务咨询全闭环。

Pain Points & Technical Bottlenecks
CORE DILEMMA
核心工程矛盾
高准确率、低延迟响应、零显卡算力成本与高隔离前端接入之间的极致平衡。
🔍 业务与技术瓶颈三维解构
1. 语义与字面鸿沟：群众口语化长句提问与政务公文规范化用词存在巨大代沟，传统全文检索粗召漏检率高达 40% 以上。

2. 算力与部署鸿沟：主流开源重排模型（如 BGE-Reranker）依赖 GPU 算力，单机私有化运维成本极高。

3. 浏览器协议鸿沟：政务官网 HTTPS 环境严禁调用混合协议（Mixed Content），传统第三方插件极易被浏览器直接静默拦截。

02 研究思路与理论
总体微服务拓扑与双引擎驱动架构
System Architecture & Dual-Engine Topology
🏗️ 架构层次拓扑
[ 客户端展现层 ] └─ Shadow DOM 悬浮外挂 (叻仔) │ (SSE 流式推流 / POST) [ 服务网关控制层 ] └─ Spring Boot 3 Controller (REST/SSE) │ [ 核心计算双引擎 ] ├─ 引擎A: RAG 检索增强引擎 (FTS5 + ONNX) └─ 引擎B: Spring AI 决策推理引擎 (ChatClient) │ [ 底层数据仓储层 ] └─ 4.4GB 结构化政务库 + FTS5 倒排索引
⚙️ 双引擎协同工作原理
引擎 A (RAG 检索增强)：负责对 4.4GB 原始政务数据进行精准分块、jieba 短词倒排粗召与 ONNX 语义精排，提炼权威上下文。

引擎 B (Spring AI 推理)：通过 ChatClient Fluent API 注入上下文，挂载 AuditLoggingAdvisor 切面，通过 SSE 单向推流实时回传前端。

架构核心原则：高内聚低耦合、零外部中间件强依赖、全链路反应式背压。

03 研究内容与展示
核心工程攻关与疑难排查复盘
Critical Engineering Obstacles & Solutions
01 分词短词漏召回排查
现象：用户检索“中公教育”无法召回。
排查：jieba 默认模式切分为单字，导致倒排索引丢失词根。
方案：重写 QueryCompiler，定制政务专有名词词典与 unicode61 字符集。
02 WebClient 内存溢出破解
现象：注入多篇政务长文时触发 DataBufferLimitException (256KB)。
排查：Spring WebFlux 底层 Netty 默认缓冲上限过小。
方案：调优 ExchangeStrategies 缓冲区至 64MB，完美承受高吞吐数据流。
03 SSE 游离连接与内存泄漏
现象：客户端异常关闭导致服务端 SseEmitter 未能注销。
方案：增加 Heartbeat 心跳探活机制与 onError/onTimeout 兜底回收回调。
04 前端横向滚动条打架攻克
现象：提问历史与推荐词条水平排布，鼠标滚轮无法直接滑动。
方案：动态捕获 WheelEvent 事件，转换为 scrollLeft 增量，配置吸附平滑滚动。

04 总结分析与展望
工程反思与现存不足剖析
Engineering Reflections & Limitations
DEFECT 01
高并发 CPU 排队延迟
纯 CPU 精排在超过 50 个高并发请求同时涌入时，CPU 利用率可能接近饱和，后续需引入两级 LRU 本地缓存机制。
DEFECT 02
SQLite 水平扩展局限
SQLite 适合单机低成本极速部署，若未来向跨节点分布式部署演进，需考虑向 Milvus / PGVector 向量引擎平滑过渡。
DEFECT 03
多轮消歧长上下文开销
当前多轮对话完整保留上下文可能带来 Token 消耗累积，未来可引入轻量总结 Agent 定期压缩历史对话摘要。
DEFECT 04
移动端自适应排版深度
目前主要针对 PC 端政务服务大厅做了高精度像素适配，移动端政务 App 或微信小程序的适配细节仍可继续深化。
